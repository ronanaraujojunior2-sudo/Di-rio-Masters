REGRAS DO FIRESTORE — DIÁRIO DE BORDO MASTERS

Regra de acesso definida:
- MASTERS (perfil administrador): lê todos os registros e administra o sistema.
- RONAN (perfil usuario): lê e altera somente viagens e abastecimentos cujo uid seja o próprio UID.
- Veículos: leitura para usuários ativos; cadastro/alteração/exclusão somente MASTERS.
- Registros antigos sem uid: somente MASTERS consegue consultá-los. Eles não são atribuídos automaticamente a ninguém.

Antes de publicar, confirme em usuarios/{UID_MASTERS}:
uid = UID real da conta MASTERS
usuario = MASTERS
perfil = administrador
status = ativo

Confirme em usuarios/{UID_RONAN}:
uid = UID real da conta RONAN
usuario = RONAN
perfil = usuario
status = ativo

Substitua as regras atuais em Firebase Console > Firestore Database > Regras por:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function logado() { return request.auth != null; }
    function perfilExiste() {
      return logado() && exists(/databases/$(database)/documents/usuarios/$(request.auth.uid));
    }
    function ativo() {
      return perfilExiste() &&
        get(/databases/$(database)/documents/usuarios/$(request.auth.uid)).data.status == 'ativo' &&
        get(/databases/$(database)/documents/usuarios/$(request.auth.uid)).data.uid == request.auth.uid;
    }
    function admin() {
      return ativo() &&
        get(/databases/$(database)/documents/usuarios/$(request.auth.uid)).data.perfil == 'administrador' &&
        get(/databases/$(database)/documents/usuarios/$(request.auth.uid)).data.usuario == 'MASTERS';
    }
    function donoAtual() {
      return ativo() && resource.data.uid == request.auth.uid;
    }

    match /usuarios/{userId} {
      allow get: if ativo() && (request.auth.uid == userId || admin());
      allow list: if admin();
      allow create, update, delete: if admin();
    }

    match /veiculos/{id} {
      allow get, list: if ativo();
      allow create, update, delete: if admin();
    }

    match /viagens/{id} {
      allow get, list: if admin() || donoAtual();
      allow create: if admin() || (ativo() && request.resource.data.uid == request.auth.uid);
      allow update: if admin() || (donoAtual() && request.resource.data.uid == resource.data.uid);
      allow delete: if admin() || donoAtual();
    }

    match /abastecimentos/{id} {
      allow get, list: if admin() || donoAtual();
      allow create: if admin() || (ativo() && request.resource.data.uid == request.auth.uid);
      allow update: if admin() || (donoAtual() && request.resource.data.uid == resource.data.uid);
      allow delete: if admin() || donoAtual();
    }

    match /reservas/{veiculoId} {
      allow get, list: if ativo();
      allow create: if ativo() && request.resource.data.uid == request.auth.uid && request.resource.data.status == 'ativa';
      allow update: if ativo() && (
        (resource.data.status != 'ativa' && request.resource.data.uid == request.auth.uid && request.resource.data.status == 'ativa') ||
        (resource.data.uid == request.auth.uid && request.resource.data.uid == resource.data.uid && request.resource.data.status == 'liberada') ||
        (admin() && request.resource.data.status == 'liberada' && request.resource.data.liberacaoAdministrativa == true)
      );
      allow delete: if admin();
    }

    match /historico_reservas/{id} {
      allow get, list: if admin() || donoAtual();
      allow create: if admin() || (ativo() && request.resource.data.uid == request.auth.uid);
      allow update, delete: if admin();
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

ATENÇÃO À MIGRAÇÃO:
1. Publique primeiro as regras acima.
2. Entre como MASTERS e use "Enviar dados locais (administração)" uma única vez no aparelho que contém os registros antigos.
3. Os registros antigos sem uid serão marcados como legado e permanecerão visíveis apenas ao MASTERS.
4. Entre como RONAN em outro aparelho e confirme que ele só recebe os próprios registros.
5. Crie uma viagem e um abastecimento de teste como RONAN; confirme que aparecem no MASTERS e não aparecem em outra conta de usuário.
6. Não limpe o armazenamento do navegador e não exclua documentos existentes durante os testes.

As regras são aplicadas no servidor pelo Firestore. Ocultar botões na interface não substitui estas regras.
